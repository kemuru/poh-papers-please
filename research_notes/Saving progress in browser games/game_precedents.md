## 1. Papers, Please: how saving, day select, branches, mid-day quits and endings work

### Takeaway
Papers, Please (desktop) autosaves once per day, at the day boundary, into a branching "story tree": from the day-select screen you can load any saved day, and playing it creates a new branch instead of overwriting the old one (up to about five branches visible, with a trashcan to prune). Nothing is saved mid-day on desktop, so quitting mid-shift sends you back to that morning; the 2014 iPad port listed "mid-day resume" as a new feature. The developer calls the branching system possibly "overkill", reviewers and players call it one of the best things in the game, and it turns replaying days into the intended way to find the 20 endings.

### Cited Findings
- **Save timing, from the developer.** Lucas Pope (Steam name dukope), 3 Oct 2013: "The game should automatically save at the start of each day." A player earlier in the same thread (Fraggle, 1 Sep 2013): "When you finish a day the game will save automatically. If you fail a day there will be no save game of this day." A later player found the desktop save file named `save.sol`. — [Steam: "Saving progress?"](https://steamcommunity.com/app/239030/discussions/0/846963165520653258/)
- **The branching design was deliberate.** Lucas Pope tweet, 29 Jun 2013 (#screenshotsaturday): "The save system in Papers Please supports branching from any day. Might be overkill." (Text taken from the search-result title; the X page did not load, and the date is decoded from the tweet ID.) — [X/@dukope](https://x.com/dukope/status/350919332613726208)
- **Replaying an earlier day creates a branch.** Players: "it makes a new file after finishing the day"; "all new games you perform from earlier days become new lines in the saved games page. It looks like a horizontal tree." Another player: "Papers has like the greatest save system in the known universe... we should do that 100% of time from now on." — [Steam: "What happens if you start from an earlier day?"](https://steamcommunity.com/app/239030/discussions/0/846963165518024014/)
- **Nothing is overwritten, but deletes cascade.** Barking Sands, 10 Feb 2014: "It creates a new branch from the original savedays so nothing is overwritten. You can return to your original game files or redo the last few days without getting rid of the first set of saves." Celloheaven: "when you delete from one point of a branch, all the progress after that day in that branch will also be deleted." Ivangelo: "a great way for farming achievements or if you want a slight different ending." — [Steam: "Redoing a day?"](https://steamcommunity.com/app/239030/discussions/0/540732889589548915/)
- **Day-select screen and new game.** "In the screen where you select on which day you want to continue, either just select day 1 or use the little trashcan icon in the lower right to delete current saves." — [Steam: "Is there a way I can reset to the beginning?"](https://steamcommunity.com/app/239030/discussions/0/485624040229142358/); also [Steam: "Can't delete saves"](https://steamcommunity.com/app/239030/discussions/0/5729109343954486008/) ("Click the trashcan icon on the day select screen then pick which days you'd like to erase"). So there is no separate "New Game" slot: starting over means picking Day 1 (which makes a new branch) or deleting saves.
- **Branch limit.** The in-game message reads "Save Branch Full: Please delete branch from the most right". A player (triock) says you "can have up to five branches". — [GOG forum: "Save Game Branches Full?"](https://www.gog.com/forum/papers_please/save_game_branches_full)
- **Implementation: one save per day plus a header file.** In July 2014 Pope explained that a header file stores the save "tree" (which save connects to which). Without it, "it's just a bunch of floating day saves." He hand-wrote code to rebuild a fan's header, and noted "you'll still need to delete at least one track if you decide to branch somewhere" because only so many tracks fit on screen. — [KitGuru, 7 Jul 2014](https://www.kitguru.net/gaming/jon-martindale/papers-please-dev-personally-fixes-fans-save-files/)
- **Reviewer view of the system.** "You're able to load any day, and taking different actions on that day splits following days into their own timeline which you can do the same with." It lets you "go a few days forward to see how it plays out before ultimately going back". The reviewer calls the system "shockingly great" and says some story beats are "upsetting to the point that you'll reload your game save over and over just to see if there's any chance you can make different decisions to prevent it." — [TouchArcade iPad review, 15 Dec 2014](https://toucharcade.com/2014/12/15/papers-please-for-ipad-review/)
- **Mid-day resume is a mobile addition.** The iOS/iPad listing: "Includes the complete original game with all 31 days and 20 endings. Also adds unlockable multitouch support..., an enhanced inspection mode, Game Center achievements, leaderboards, **mid-day resume**, and more." — [App Store](https://apps.apple.com/us/app/papers-please/id935216956); same list in [iMore](https://www.imore.com/papers-please-makes-its-ipad-debut-without-nudity-pc-version)
- **Replaying for endings is designed in.** Analysis: "Players are not punished heavily for making the wrong choices because they do not have to redo the entire game to discover a particular ending... When players are faced with an ending that they are not satisfied with, players can retrace their steps on that current timeline and restart on a day before they made that fateful choice." (Secondary, fan/student site.) — [choice-in-games](https://nadyabbq.wixsite.com/choice-in-games/blank)
- **Days are scripted, so a replayed day is the same day.** A player: "The story doesn't really branch. You go through the same events every time, but your actions and responses to those events determine your ending." — [Steam: "Where do the stories start branching?"](https://steamcommunity.com/app/239030/discussions/0/846961716427177096/)
- **Scale.** A scripted story with 20 possible endings, plus unlockable randomized endless modes, "limited only by the player's error count". — [Wikipedia: Papers, Please](https://en.wikipedia.org/wiki/Papers,_Please). There are 31 playable days, 23 Nov to 23 Dec 1982 (search excerpt, page not fetched) — [Papers Please Wiki: Timeline](https://papersplease.fandom.com/wiki/Timeline). Endings achieved are shown on the day-selection screen (search excerpt of the Endings page, page not fetched) — [Papers Please Wiki: Endings](https://papersplease.fandom.com/wiki/Endings)
- **Cloud sync is fragile.** Steam Cloud syncs saves by default, but one player syncing between two PCs "bugged out so I was up to the day from the second run but every day was actually the first day." — [Steam: "Is the story progress of PP saved online or offline?"](https://steamcommunity.com/app/239030/discussions/0/617320168002394942/)

### Inferences
- The two save-timing statements agree. The save written when day N ends is the save for the start of day N+1, and a day that ends in a game over never produces a save. Reloading therefore always drops you at a morning: in Papers, Please each day opens on the newspaper (search excerpt of wiki Timeline).
- The desktop version has no mid-day save. Pope says saves happen at day start, and the iPad port advertised "mid-day resume" as an added feature. So quitting mid-shift on PC restarts the day from its morning. This is inferred, not stated verbatim by the developer.
- This maps almost one-to-one onto our game: newspaper in the morning, shift, then accounts. The Papers, Please precedent is to checkpoint at the morning screen, offer a day-select screen (at least after an ending or a firing), and treat replaying a day as a feature, not an exploit. With a seed-deterministic week, a replayed day shows the same applicants, like Papers, Please's scripted days.

### Gaps
- No primary developer statement found on exactly what desktop Papers, Please does on a mid-day quit (Pope's TIGSource devlog and mobile devlog have no save discussion: [devlog scrape](https://fguillen.github.io/PapersPleaseDevlogScrap/), [mobile devlog](https://dukope.com/devlogs/papers-please/mobile/)).
- Unknown whether the iPad "mid-day resume" restores the in-game clock exactly or restarts from the current entrant.
- The exact post-ending flow (whether the game offers "restart this day" directly or only returns to the menu and timeline) could not be confirmed, because the Fandom wiki was blocked.
- The Endless mode save behaviour was not found.

## 2. Comparable games: save granularity, mid-level quit, slots, chapter select and new-game flows

### Takeaway
Narrative desk and choice games split into two camps. **Day checkpoint with replay** (Papers, Please, Not Tonight, Death and Taxes, Headliner) saves at day boundaries, lets you go back to a day, and loses mid-day progress. **Continuous autosave with no undo** (Obra Dinn, Orwell, Hypnospace Outlaw, Beholder at events) saves on every meaningful action or every few minutes and resumes where you left off. Browser and daily web games (Wordle, 2048, A Dark Room, Cookie Clicker) are uniformly continuous: state goes to localStorage after every move, or every 60 seconds for idle games, and a refresh resumes exactly.

### Cited Findings

**Return of the Obra Dinn (Lucas Pope, 2018)**
- Continuous autosave, no manual save and no slots. Player, 14 Apr 2019: "I'm quite sure it auto-saves. There are no save points, no menu option to save, and you don't need to quit to save. Alt+F4 is safe, as well." — [Steam: "How does Saving work?"](https://steamcommunity.com/app/653530/discussions/0/2605804632889241322/)
- Opening the Esc menu triggers an autosave, shown by an icon in the lower left (search excerpt, page not fetched). — [Twinfinite guide](https://twinfinite.net/guides/return-of-the-obra-dinn-save-game/)
- Since v1.1.110 the game "makes backup saves periodically during gameplay, in the hope of recovering progress if the game crashes or if something goes wrong with cloud saving" (search excerpt of 3909's support page, page not fetched). — [3909 Support: Savefile Backups](https://3909.zendesk.com/hc/en-us/articles/360022216013-Savefile-Backups)
- Brute-forcing is blocked by design, not by the save system: "to deter guesswork, correct fates are validated only in sets of three." — [Wikipedia: Return of the Obra Dinn](https://en.wikipedia.org/wiki/Return_of_the_Obra_Dinn)

**Not Tonight (PanicBarn / No More Robots, 2018): a Papers, Please-like bouncer game**
- Three save slots. Going back copies the timeline instead of overwriting it: "When you go back to a previous day, instead of deleting all your progress after that point, the game copies your game over into a new save slot so that you can always go back to the original if you like." If all 3 slots are used, you must delete one. (Reply attributed to developer staff by the page summary; not re-verified.) — [Steam: "Resetting a day"](https://steamcommunity.com/app/733790/discussions/0/1734343065614647535/)
- Developer (TinyPixxels, [developer]): "It was designed so that you could pick different options in a day and have two 'timelines' running so that you could see the consequences of certain actions!" — [Steam thread](https://steamcommunity.com/app/733790/discussions/0/3194747223957163518)
- Players complained about the result. "Loading a slot from the last checkpoint fills the next empty one and keeps rolling from there, so the previous save stops recording game progress." "When you reload you have to delete a slot. I accidentally deleted my whole game when I died from exhaustion." "I just wanted to continue on one single save slot, but it filled up all three slots." — [same thread](https://steamcommunity.com/app/733790/discussions/0/3194747223957163518)

**Death and Taxes (Placeholder Gameworks, 2020): desk game where you stamp who dies**
- One active save file (`Save.RIP`) plus automatic backups for each passed day. The developer (Oakwarrior): "We don't have custom save game management in the game as the game wasn't designed like that." Swapping players means renaming files by hand. — [Steam: "Multiple saves?"](https://steamcommunity.com/app/1166290/discussions/0/3084382396863156916/)
- During a 2020 save-loss bug, the developer told players to restore `SaveBackups/…DayX` by renaming it to `Save.RIP`. A player said the backup "started me from the very end of the last one", which suggests day-boundary saves. There is no in-game way to reload an earlier day. — [Steam: "Game reset progress after an exit and restart"](https://steamcommunity.com/app/1166290/discussions/0/1744519654625372120/)

**Orwell (Osmotic Studios, 2016): surveillance desk game with permanent uploads**
- No chapter restart at launch. Developer (Osmotic Dan), 29 Oct 2016: "at the moment you'll have to create a new profile and start the game over. You cannot restart individual chapters." In the same thread a player "pressed Alt+F4 no more than two seconds later. But my progress was still saved", so the game saves per action. — [Steam: "How to restart chapter?"](https://steamcommunity.com/app/491950/discussions/0/305509857568739839/)
- Permanence is part of the fiction. A player (not tagged developer): "The game specifically tells you that the uploading of information can not be undone and is final. It's an integral part to the game and narrative." Others asked for an undo button, or "at least... a confirm option". — [Steam: "How to Undo"](https://steamcommunity.com/app/491950/discussions/0/152392786900354473/)
- In the sequel, "Reloading a specific day is only available after you've completed the third episode, at least according to the profile options screen" (player, Mar 2018). — [Steam: Orwell: Ignorance is Strength](https://steamcommunity.com/app/633060/discussions/0/1697167355212154994/)

**Beholder (Warm Lamp Games, 2016)**
- Autosave only. A player (illbgreat): "The game autosaves after quests and important events"; players are told to "wait for a save icon in the corner of the scene before you leave the game." Several players lost 45 minutes or more of quests despite seeing the icon. — [Steam: "when does this game save?"](https://steamcommunity.com/app/475550/discussions/0/1738841319822082209/)
- Older autosaves can be loaded from the Saves folder. The top request: "I want to be able to save when I want... and not have my saves overwritten at the next checkpoint." — [Steam: "Please make manual save game feature!"](https://steamcommunity.com/app/475550/discussions/0/135514287301693315/)
- Beholder: Conductor (2024+) reportedly has "autosave at every station, and you can load any autosave" (search excerpt, page not fetched). — [Steam](https://steamcommunity.com/app/2825530/discussions/0/603037883163635741/)

**Reigns: Game of Thrones (Nerial, 2018)**
- Saves only when a reign ends: "There doesn't seem to be a way to save progress during the actual reign. When I quit the game and start it again, it always starts at the last death." A reign can run 20 to 30+ minutes, and players objected to losing one to an interruption (25 Apr 2019). — [GamingOnLinux forum](https://www.gamingonlinux.com/forum/topic/3860/); also [Steam: "No save option within one run?"](https://steamcommunity.com/app/897820/discussions/0/1733216261962922425/) ("A save & quit option would be much appreciated!"; on return "the game started off at the finish screen of the beforehand run").
- Original Reigns: a full reset is hidden behind "hold R for 5 seconds", and the gallery and memento mori survive even a cache wipe. — [Steam: "Starting New Save"](https://steamcommunity.com/app/474750/discussions/0/355043117508657412/)

**Hypnospace Outlaw (Tendershoot, 2019)**
- "saving is automatic every few minutes and also whenever you click the log out button." Developer (TetroniMike, [developer], 7 Nov 2025): "As long as you make sure to log out before you close the game, yes!" — [Steam: "can you save whenever you want?"](https://steamcommunity.com/app/844590/discussions/0/616556383851089791/)
- Three slots (`Enforcer1.sav` to `Enforcer3.sav`) (search excerpt, page not fetched). — [GOG support](https://support.gog.com/hc/en-us/articles/360019527454-Hypnospace-Outlaw). A 2024 patch moved saves to a standard directory "to better support cloud saves". — [itch devlog, 28 Mar 2024](https://jay-tholen.itch.io/hypnospace-outlaw/devlog/705574/saves-surprises-update)

**Headliner: NoviNews (Unbound Creations, 2019): day-by-day news-approval desk game**
- "Headliner Autosaves at when you sleep in your apartment." Quitting to the main menu and reloading "will restart the day with refreshed articles, it's helpful when aiming for specific routes." That is an official day-restart path which also rerolls content. — [Knoef trophy guide](https://knoef.info/trophy-guides/ps4-guides/headliner-novinews-trophy-guide/)
- Persistent data such as furniture carries across playthroughs. The developer (Koobazaur) documented a config flag to reset it, which "doesn't delete your saves". — [Steam: "3 play through cycle"](https://steamcommunity.com/app/918820/discussions/0/1637536330478610835/)

**Blue Prince (Dogubomb, 2025): day-structured runs, the closest recent debate**
- No mid-day save; "Save & Quit" ends the day. Players (Apr 2025 to Mar 2026): "just let the 'save and quit' option let you quit without ending the day". Some leave the PC running overnight: "you are forcing me to keep the pc running whenever I... need to step away midrun". Another: "As long as there is only one save and it loads at the exact same state there would be no way of exploiting it." Another suggests autosaving "whenever you entered a room, drafted a room... or made a purchase" to stop scumming. A 300-hour player now says mid-day save should not be added. — [Steam: "Please allow mid day save/load"](https://steamcommunity.com/app/1569580/discussions/0/599651004551572825/)
- The trade-off, stated by players: "adding midday save would create the ability to save-scum when drawing rooms, and that would utterly destroy it". The counter: "Most games have a save and once you reload it deletes the save." One player would refund because it "doesn't really respect my time." — [Steam: "No mid-run save?"](https://steamcommunity.com/app/1569580/discussions/0/687490776811317254/). A moderator called mid-day saves "one of the most requested features" (page summary, not re-verified). — [Steam](https://steamcommunity.com/app/1569580/discussions/0/691999379595296274/)

**Slay the Spire (seeded roguelike, useful for determinism)**
- Save & Quit in the middle of combat reloads at the start of that fight with the same RNG: "Nothing changes compared to before pressing it, the cards come out in the exact same order." Players are split on whether it is an exploit, and one claims the developers consider it a feature (unverified). — [Steam: "Discovered Save & Quit and don't like it"](https://steamcommunity.com/app/646570/discussions/0/5208960061387585960/); [Steam: "Do you Save & Quit?"](https://steamcommunity.com/app/646570/discussions/0/1699416432429878829/) (suggestions include a score penalty for quitting mid-fight).

**Wordle (daily web game, localStorage)**
- State lives in localStorage under `gameState`, with fields `boardState`, `evaluations`, `rowIndex`, `solution`, `gameStatus`, `lastPlayedTs`, `lastCompletedTs`, `restoringFromLocalStorage` and `hardMode`. — [Taq Karim, 24 Jan 2022](https://mottaquikarim.github.io/dev/posts/reverse-engineering-wordle/)
- "Wordle uses what's called local storage to save your most recent game and your history. The most recent game information is stored in `gameState` and the history in `statistics`" (streaks, guess distribution). — [leancrew, Feb 2022](https://leancrew.com/all-this/2022/02/resurrecting-the-old-wordle-for-procrastinators/)
- Storage is tied to the origin. After the move to nytimes.com on 10 Feb 2022, "some users reported that their daily streaks had reset". — [Wikipedia: Wordle](https://en.wikipedia.org/wiki/Wordle). Streak data "is stored locally, a combination of the user's device, browser, and URL". The NYT advised opening the old URL once so it would redirect and carry the stats (search excerpt, page not fetched). — [Kotaku](https://kotaku.com/wordle-new-york-times-streaks-broken-nyt-migration-dail-1848525236); [Forbes](https://www.forbes.com/sites/erikkain/2022/02/11/why-are-my-wordle-stats-and-streak-reset-and-is-there-a-fix/)

**2048 (browser, open source)**
- `LocalStorageManager` keys: `bestScore` and `gameState`. After every move, `actuate()` calls `setGameState(this.serialize())`, or `clearGameState()` when the game is over. `setup()` reloads the previous state if one exists, and "New Game" (`restart`) clears it. So a refresh resumes exactly, and game over erases the save. — [game_manager.js](https://github.com/gabrielecirulli/2048/blob/master/js/game_manager.js); [local_storage_manager.js](https://github.com/gabrielecirulli/2048/blob/master/js/local_storage_manager.js)

**A Dark Room (browser narrative/incremental, open source)**
- `Engine.saveGame()` writes the whole state, `localStorage.gameState = JSON.stringify(State)`. The state manager calls `saveGame()` on every `$SM.set` and `setM`, i.e. every state change. A "saved" notice flashes at most once every 30 s (`SAVE_DISPLAY: 30 * 1000`). Export and import go through a Base64 string. — [engine.js](https://github.com/doublespeakgames/adarkroom/blob/master/script/engine.js); [state_manager.js](https://github.com/doublespeakgames/adarkroom/blob/master/script/state_manager.js)

**Cookie Clicker (idle/incremental)**
- "Game progress is saved automatically every 60 seconds". Ctrl+S saves manually. Saves live in browser storage, which allows "the tab or web browser to be closed, or the PC to be turned off, without losing game progress". Export/import uses a string, and "Wipe save" is irreversible. — [Cookie Clicker Wiki: Save](https://cookieclicker.wiki.gg/wiki/Save)

### Inferences
Synthesis table, derived from the findings above:

| Game | When it saves | Quit mid-level/day | Slots / branches | Day or chapter select | New game |
|---|---|---|---|---|---|
| Papers, Please (PC) | Start of each day | Restart that day (inferred); iPad adds mid-day resume | Tree, about 5 branches | Yes, any saved day | Pick Day 1 or trash saves |
| Not Tonight | Per day plus autosaves | Day-based | 3 slots, reload copies to a new slot | Yes | Slot-based |
| Death and Taxes | End of each day | Back to the day-boundary save (likely) | 1 save + hidden per-day backups | No (files only) | New game / NG+ |
| Headliner: NoviNews | When you sleep (end of day) | Restart the day, articles rerolled | Not documented | No; the loop rewinds on replay | Replay cycles, persistent furniture |
| Orwell | Per action | Resume exactly, mistakes stick | Profiles | Only after episode 3 (sequel) | New profile |
| Obra Dinn | Continuous, plus on Esc | Resume exactly | 1 | No | New game |
| Hypnospace Outlaw | Every few minutes + on logout | Up to a few minutes lost | 3 | No | Slot |
| Beholder | After quests and events | Back to the last event | Multiple autosaves | Via files | — |
| Reigns: GoT | Only at death | Back to the last death | 1 | No | Hold-to-reset (Reigns) |
| Blue Prince | End of day | Day ends or is lost | 1 | No | — |
| Wordle / 2048 / A Dark Room | Every move | Resume exactly | 1 (localStorage) | No | Restart clears the save |
| Cookie Clicker | Every 60 s | Up to 60 s lost | 1 + export | No | Wipe |

- Every desk and choice game with a day structure uses the day as the checkpoint unit. None of the narrative desk games found restores an in-progress shift on desktop. Mobile ports and web games do resume mid-session.
- Multi-slot and branching schemes create UI debt. Not Tonight's copy-on-reload filled all three slots and led to accidental deletions, and Papers, Please needed a branch cap and a trashcan. A small browser game gains most of Papers, Please's value from a linear day list (one save per day start) without a branch tree.

### Gaps
- Mars After Midnight, Paper Trail and Hypnospace's chapter structure were not researched in depth.
- No primary source on Not Tonight's autosave frequency within a night.
- The original Reigns' mid-reign behaviour was not confirmed; only the Game of Thrones spin-off is documented.
- Death and Taxes' exact mid-day quit behaviour is not stated by the developer.

## 3. Save-scumming in games with consequences and timers: prevent, allow or embrace? And refresh-as-undo in browser games

### Takeaway
Papers, Please-likes mostly embrace day-level replay as a way to explore consequences, keep permanence inside a day or action, and deter brute-forcing through mechanics rather than save restrictions. Papers, Please and Not Tonight branch timelines, Headliner rerolls the day, and Obra Dinn confirms fates only in threes. The hard-line cases are Orwell (every action saved, no undo, no chapter restart at launch), Reigns: GoT (save only at death) and Blue Prince (no mid-day save). All of them drew a steady stream of player complaints. In browser games the norm is to save after every action (Wordle, 2048, A Dark Room), which kills refresh-as-undo by construction. Design writing leans toward "players must be able to stop without losing meaningful progress". Players repeatedly propose a single suspend save that is overwritten continuously and consumed on load, which reconciles "resume" with "no scumming".

### Cited Findings
- **Embrace, at day granularity.** Papers, Please's branching lets players "restart on a day before they made that fateful choice" ([choice-in-games](https://nadyabbq.wixsite.com/choice-in-games/blank)). Players use it for "farming achievements or if you want a slight different ending" ([Steam: "Redoing a day?"](https://steamcommunity.com/app/239030/discussions/0/540732889589548915/)). Pope himself built it to branch "from any day" ([X/@dukope](https://x.com/dukope/status/350919332613726208)).
- **Embrace, via parallel timelines.** Not Tonight's developer: designed "so that you could pick different options in a day and have two 'timelines' running so that you could see the consequences". — [Steam](https://steamcommunity.com/app/733790/discussions/0/3194747223957163518)
- **Embrace, via reroll.** In Headliner, quitting and reloading "will restart the day with refreshed articles, it's helpful when aiming for specific routes". — [Knoef guide](https://knoef.info/trophy-guides/ps4-guides/headliner-novinews-trophy-guide/)
- **Deter through mechanics, not saves.** Obra Dinn: "to deter guesswork, correct fates are validated only in sets of three." — [Wikipedia](https://en.wikipedia.org/wiki/Return_of_the_Obra_Dinn)
- **Prevent, through per-action saves.** Orwell saved within about two seconds of a mistake despite Alt+F4, and the developer said chapters could not be restarted ([Steam](https://steamcommunity.com/app/491950/discussions/0/305509857568739839/)). Players defended the permanence as "integral to the game and narrative" ([Steam](https://steamcommunity.com/app/491950/discussions/0/152392786900354473/)). The sequel unlocks day reload only after episode 3 ([Steam](https://steamcommunity.com/app/633060/discussions/0/1697167355212154994/)).
- **Prevent, through saving only at run end.** Reigns: GoT restarts at the last death ([GamingOnLinux](https://www.gamingonlinux.com/forum/topic/3860/)). Blue Prince has no mid-day save, and players read that as anti-scum intent: "the devs dont want people save scumming" ([Steam](https://steamcommunity.com/app/1569580/discussions/0/687490776811317254/)).
- **Deterministic reload makes scumming a rehearsal, not a reroll.** Slay the Spire reloads a fight with "the cards come out in the exact same order". Some call this a free "repeat" button that "removes the damage control part of the game"; others accept it because it is single-player. — [Steam](https://steamcommunity.com/app/646570/discussions/0/5208960061387585960/)
- **Industry framing.** A working developer (@askagamedev) lists the options: remove randomness, "lock results per playthrough", extreme randomness, optional objectives, or "enforce autosaves only". Which to use depends on "whether save scumming represents an actual problem". — [askagamedev (Tumblr)](https://www.tumblr.com/askagamedev/664775102667325440/save-scumming-is-often-a-critique-in-how-you-can)
- **Roguelike convention.** Most roguelikes prevent save-scumming "by erasing a save file as soon as you load it" (search excerpt, page not fetched). — [TV Tropes: Save Scumming](https://tvtropes.org/pmwiki/pmwiki.php/Main/SaveScumming). Players cite the same pattern for Blue Prince: "once you reload it deletes the save" ([Steam](https://steamcommunity.com/app/1569580/discussions/0/687490776811317254/)).
- **Autosave as an anti-cheat.** Mega Man Battle Network's chip traders autosave on each dispense so players "can't cheat by soft resetting" (search excerpt, page not fetched). — [Wikipedia: Autosave](https://en.wikipedia.org/wiki/Autosave)
- **Browser games save on every action.** 2048 writes `gameState` after every move and clears it on game over ([game_manager.js](https://github.com/gabrielecirulli/2048/blob/master/js/game_manager.js)). A Dark Room saves on every state change ([state_manager.js](https://github.com/doublespeakgames/adarkroom/blob/master/script/state_manager.js)). Wordle stores board, row index and status ([Taq Karim](https://mottaquikarim.github.io/dev/posts/reverse-engineering-wordle/)). In all three, reloading the tab cannot undo a move.
- **The "player's right" position.** David Sirlin (Game Developer, 2008): "Players should be able to save anytime they want, or more precisely, they should be able to stop playing your game anytime without losing their meaningful progress." And: "Saving should be treated as one of the player's natural rights, not an earned privilege or a game mechanic around which to make strategic decisions." — [Game Developer: "Saving the Day"](https://www.gamedeveloper.com/design/saving-the-day-save-systems-in-games)

### Inferences
- For a seed-deterministic week, a restart-the-day-on-refresh model means a refresh replays the same applicants with the same clues. That is Slay the Spire-style rehearsal: the player can memorise who is invalid and redo the shift perfectly. Papers, Please accepts exactly this, since its days are scripted and replayable from the day select, so it is a known and accepted trade.
- Refresh-as-undo is only a problem if the undo point is closer than the player's decision. Per-action saves (Wordle, 2048, A Dark Room, Orwell) remove it. Day-start checkpoints (Papers, Please) turn it into "redo the whole day", which costs a full shift of time and so self-limits.
- The recurring player-proposed compromise (Blue Prince threads) is: autosave on every action into one suspend slot, resume exactly, and offer "restart day" only as an explicit, visible action.

### Gaps
- No published designer statement from Lucas Pope on why Papers, Please omitted mid-day saves on desktop.
- No developer statement from Dogubomb on the Blue Prince mid-day save decision.
- No formal survey or consensus document specifically on "refresh-as-undo" in browser games. The evidence is the de facto implementations above plus forum debate.

## 4. What players expect when they refresh or close a browser game tab

### Takeaway
Player evidence consistently shows that losing progress on close or interruption is a top complaint and a refund reason. The expectation in web and daily games is exact resume, as Wordle, 2048, A Dark Room and Cookie Clicker all behave. Browser storage adds its own failure modes that surprise players: origin changes, iframe partitioning, iPad and Safari, cleared data. Choosing between "resume exactly" and "restart the current level" matters less than never silently losing more than one short unit of play.

### Cited Findings
- **Lost progress surprises players, even with localStorage.** WhaleBunny (itch.io dev forum, 3 Jul 2021): "We can save to localstorage, but that data can be lost - I have players reporting that they're surprised their progress has suddenly gone away!" — [itch.io: "Revisiting the storage question for HTML5 Games"](https://itch.io/t/1504924/revisiting-the-storage-question-for-html5-games)
- **Origin changes wipe saves.** Omiod (Sep 2022): "after an update the game is stored on a different address, and all the data is lost... at every update the CDN address changes." Other developers reported no loss, so the behaviour depends on build and engine. — [itch.io: "HTML5 local storage is lost at every update"](https://itch.io/t/2346400/html5-local-storage-is-lost-at-every-update)
- On iPad, localStorage calls reportedly succeed but do not persist across reloads for itch.io HTML5 games (search excerpt, page not fetched). — [itch.io thread](https://itch.io/t/2636350/localstorage-doesnt-work-for-html5-games-on-ipad-by-default)
- **The Wordle origin migration** lost some players' streaks, because the data was local and tied to the device, browser and URL. — [Wikipedia: Wordle](https://en.wikipedia.org/wiki/Wordle); [Kotaku](https://kotaku.com/wordle-new-york-times-streaks-broken-nyt-migration-dail-1848525236) (search excerpt)
- **Frustration from mid-session loss in day-structured games.**
  - Blue Prince: "I just don't have the time to finish the day in one sitting". Players leave the PC in sleep mode to keep a run ([Steam](https://steamcommunity.com/app/1569580/discussions/0/691999379595296274/)). "My cat stepped on the power button twice already... Considering some runs last hours, that's a lot of progress lost" ([Steam](https://steamcommunity.com/app/1569580/discussions/0/599651004551572825/)).
  - Reigns: GoT: losing 20-minute reigns to interruptions; the player expected casual 5-minute sessions ([GamingOnLinux](https://www.gamingonlinux.com/forum/topic/3860/)).
  - Beholder: "completed a quest, quit the game" and "all the progress from that completed quest got reversed" ([Steam](https://steamcommunity.com/app/475550/discussions/0/1738841319822082209/)).
- **Frustration from irreversibility is the opposite complaint.** Orwell: "It is a game and I hate to restart because I just did something by mistake"; players asked for "a confirm option for conflicting choices" ([Steam](https://steamcommunity.com/app/491950/discussions/0/152392786900354473/)). One Orwell player considered quitting after a single mistake stuck ([Steam](https://steamcommunity.com/app/491950/discussions/0/305509857568739839/)).
- **Clear save feedback is expected.** Beholder players are told to wait for the save icon ([Steam](https://steamcommunity.com/app/475550/discussions/0/1738841319822082209/)). Obra Dinn shows a save icon when you open the menu ([Twinfinite](https://twinfinite.net/guides/return-of-the-obra-dinn-save-game/), search excerpt). A Dark Room flashes "saved" ([engine.js](https://github.com/doublespeakgames/adarkroom/blob/master/script/engine.js)). Accessibility writer Laura Dale recommends "frequent autosaves with visible confirmation" ([Access-Ability, 25 Apr 2022](https://access-ability.uk/2022/04/25/checkpoints-save-states-and-save-availability/)).
- **Accessibility argument for short retry units.** "If it takes me 20 minutes to get past a series of complex jumps, I don't want to fail a task a few minutes later and get thrown back to the part of the game I was struggling to complete." — [Access-Ability](https://access-ability.uk/2022/04/25/checkpoints-save-states-and-save-availability/)
- **Design-writing position.** Players "should be able to stop playing your game anytime without losing their meaningful progress". Sirlin's handheld examples (New Super Mario Bros., Nintendogs) show casual players driven off by coarse checkpoints. — [Game Developer (Sirlin, 2008)](https://www.gamedeveloper.com/design/saving-the-day-save-systems-in-games)
- **Hidden reset paths confuse players.** Reigns' reset is "hold R for 5 seconds", discovered only through forums ([Steam](https://steamcommunity.com/app/474750/discussions/0/355043117508657412/)). Papers, Please's reset is a trashcan icon on the day-select screen ([Steam](https://steamcommunity.com/app/239030/discussions/0/485624040229142358/)). Not Tonight's slot deletes caused accidental wipes ([Steam](https://steamcommunity.com/app/733790/discussions/0/3194747223957163518)). An explicit, confirmable "new game" flow avoids all three.

### Inferences
- In a browser, "refresh" is also how players recover from a glitch or accidentally close a tab, so a refresh that wipes the week is the worst outcome. A refresh that restarts the current ~6-minute shift from the morning is tolerable, the Papers, Please norm. A refresh that resumes exactly is the web-game norm (Wordle, 2048, A Dark Room).
- A ~6-minute shift is short compared with Blue Prince days (hours) or Reigns reigns (20 to 30 min). Restarting the day costs little, so day-start checkpointing sits near the tolerable end of the complaint spectrum.
- Because the game is local-only, the save should survive only as long as origin and storage are stable. Showing the day number on the title screen ("Continue: Day 4, morning") gives visible confirmation, which the sources say players rely on.

### Gaps
- No quantitative study (retention or abandonment data) on refresh or progress loss in browser games was found.
- No NN/g-style UX research specific to game tabs was found.

## 5. Timed levels: on resume, is the timer restored, or does the level restart?

### Takeaway
Among the games found, timed or real-time levels almost always restart, or are forfeited, rather than resuming with the timer restored. Papers, Please (PC) restarts the day, Blue Prince ends the day, Reigns: GoT returns to the last death, Slay the Spire restarts the fight, and Candy Crush charges a life for closing mid-level. Exact mid-level resume appears mainly in mobile ports (Papers, Please iPad "mid-day resume") and untimed web puzzles. Where a timer runs in a web game, the norm is to pause it when the tab is hidden (NYT Mini, reportedly). Browsers already stop `requestAnimationFrame` in background tabs.

### Cited Findings
- **Papers, Please PC:** saves only "at the start of each day" ([Steam, dukope](https://steamcommunity.com/app/239030/discussions/0/846963165520653258/)). The mobile port advertises "mid-day resume" as an addition ([App Store](https://apps.apple.com/us/app/papers-please/id935216956)), but whether the in-game clock is restored exactly is undocumented.
- **Blue Prince:** "Save and quit" ends the day, and players must "end enjoyable runs due to time restraints". — [Steam](https://steamcommunity.com/app/1569580/discussions/0/599651004551572825/)
- **Slay the Spire:** a mid-combat quit reloads "at the beginning" of the fight with identical draw order. — [Steam](https://steamcommunity.com/app/646570/discussions/0/5208960061387585960/)
- **Reigns: GoT:** quitting mid-reign returns to "the last death". — [GamingOnLinux](https://www.gamingonlinux.com/forum/topic/3860/)
- **Candy Crush Saga:** closing the tab or app mid-level costs a life without formally counting as a fail. In Soda Saga and Friends, closing the app is "equivalent to giving up" (search excerpts of the Candy Crush Fandom wikis, pages not fetched). — [Candy Crush Saga Wiki: Lives](https://candycrush.fandom.com/wiki/Lives); [Candy Crush Soda Wiki: Level Failed](https://candycrushsoda.fandom.com/wiki/Level_Failed)
- **NYT Mini Crossword:** "The timer pauses automatically if you switch to another tab" (secondary how-to site, search excerpt). — [Beebom](https://beebom.com/puzzle/how-to-play-nyt-mini-crossword/)
- **Browser behaviour relevant to shift timers:** "Most browsers stop sending `requestAnimationFrame()` callbacks to background tabs or hidden `<iframe>`s", and `setTimeout` is throttled in background tabs. `visibilitychange` is the event for detecting that the page was hidden (the place to pause or save). — [MDN: Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)
- **Obra Dinn** has no timer, but resumes exactly. It even saves when the Esc menu opens (search excerpt) ([Twinfinite](https://twinfinite.net/guides/return-of-the-obra-dinn-save-game/)). That shows "save on pause" as a pattern.

### Inferences
- The desk-game precedent for a timed shift is: do not restore the clock, restart the shift from its morning checkpoint. If our game chooses exact resume instead, the precedent from web puzzles is to store the remaining game-time, not a wall-clock end time, and pause while hidden. Otherwise a closed tab would silently run out the shift, and MDN notes that rAF-driven clocks already stall in hidden tabs while `Date.now()`-based ones do not.
- A middle option supported by precedent is a single suspend save (Blue Prince players' proposal, iPad Papers, Please's mid-day resume) holding the exact shift state and the remaining clock. It is used only to resume after an accidental close, and a separate visible "restart day" goes back to the morning.

### Gaps
- No primary source describes how the Papers, Please iPad/Android "mid-day resume" treats the in-game clock or the current entrant.
- The NYT timer-pause behaviour comes from a secondary how-to site, not NYT documentation.
- No precedent was found of a narrative desk game that restores a running shift timer exactly after a quit.
