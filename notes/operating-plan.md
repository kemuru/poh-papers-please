# My operating plan

My default process from now on, based on what the week showed (`notes/runlog.md`, `notes/report.md`).

- **Plan:** Claude Max 5x ($100 a month) alone, no API credits. Why: Claude did all the building and Max 5x never stopped work in six heavy days (over $1,100 at API prices), while Codex ran twice all week. What I give up: Codex's one review found three bugs Claude had missed; fresh Claude sessions will now do that job.
- **Upgrades:** to Max 20x ($200 a month) only when the weekly limit stops work twice in a month and the hours lost are worth more than the extra $100. I read `/usage` every evening and log each time a limit stops work.
- **Primary model and reviewer:** Opus 5.5 in Claude Code builds. A fresh Claude session reviews, never the one that wrote the code, given the task, diff and acceptance criteria and running its own checks.
- **Routing:** max effort by default, as most of the week; xhigh for bounded tasks (a skill, a `/goal`, a review pass); ultracode only when no two agents need the same file. Before keeping max as the default, compare it with xhigh on one repeated task: accepted result, review time and usage.
- **Project rules vs skills:** `AGENTS.md` stays short: architecture, design invariants, "Done means". Repeated procedures become skills (`add-applicant`). Research and style sheets live in `reports/` and `notes/`, read when relevant.
- **When graphs help:** when the work splits into parts that never edit the same file, built against a shared data shape committed first (slice 4: the court's logic in `src/court`, its screen in `src/ui`); otherwise one agent. Each writer gets its own files or worktree, port and output folder. The full e2e suite runs only in the main session.
- **Acceptance evidence:** typecheck, unit and e2e runs, with their exit codes read; a planted defect that each new check catches; screenshots I look at for any UI change; after a fix pass, a second review by an agent that made none of the fixes. Code review follows my R32 table (`notes/next.md`): the rule engine, generator and court get a fresh review and my own read before a release; the rest is checked by playing and tests.
- **Concurrency:** at most two writing agents, plus read-only ones, and no more than three running a browser (at five, two stalled). All of them share the one plan's limit. No new start while two results wait for my review. I clear them oldest first: run the checks, read the diff, then accept, send back with the failing evidence, or drop.
- **Weekly habit:** every Friday, read failed runs, the reviewer's unique findings, shared misses and usage; delete stale instructions from `AGENTS.md` and memory.
- **Reassess** after each major model release and at each renewal, including whether a second provider's review is worth a plan again. Next review: 30 Oct 2026, or the next major release if sooner (it's rumored Gemini 4 could release in October and could be the best model, better than Opus 5.5 and Astra).
